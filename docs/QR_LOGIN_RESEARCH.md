# 扫码登录能力核对

## 已接入并验证二维码

网易云音乐、QQ 音乐、QQ 音乐微信账号、酷狗、Bilibili、汽水。

全部复用当前上游 Go 登录处理。QQ 返回 Base64 内嵌图片，原生端直接解码；有二维码 URL 的平台在本机生成二维码，避免远程图片加载失败。微信轮询使用 `qq_wx` 通道，成功凭据由上游保存到 QQ 配置。汽水保留上行短信、下行验证码及扫码确认分支。

六种真实登录会话已在 Redmi 的独立测试包生成并由 ZXing 解码成功；这证明二维码有可识别内容，不证明平台账号已授权完成。真实账号关联与个人歌单同步仍需账号持有人扫码确认。

## 其他开源实现调查

检索记录位于本地忽略目录 `.firecrawl/`，未向搜索服务发送账号数据。

- [go-music-api](https://github.com/guohuiyuan/go-music-api)：同一底层库的服务版本，文档明确支持网易、QQ、微信、酷狗、Bilibili。文档的酷我、咪咕扫码项为空，未提供可直接扩展的新增通道。
- [wp_MusicApi](https://github.com/GitHub-ZC/wp_MusicApi)：包含多个音乐源，但扫码相关描述主要针对 QQ，版本记录说明曾移除基于 Android 令牌的 QQ 扫码实现；没有找到可验证的酷我/咪咕音乐扫码通道。
- [fnos_music_ext](https://github.com/javycoder/fnos_music_ext)：终端扫码能力针对网易；现有上游网易通道已覆盖此用途。

目前未找到可验证、可用于音乐账号并可直接复用的新增酷我/咪咕扫码实现。此结论仅针对本轮检索到的项目，不代表平台绝无此能力。暂不把官网链接二维码作为账号登录二维码，也不把历史接口说明当成当前可用性证明。

账号设置以“扫码关联”为主操作；有扫码的平台将 Cookie 输入折叠到“手动关联（高级）”，其余平台保留手动关联入口。

## 汽水扫码确认后停留问题

原生端曾将上游不同 scanned 状态统一显示为“已扫码，请在手机确认”，网络查询失败即退出；短信验证进入后也结束原轮询。因此界面可能停留于旧提示。现保留平台实际消息，持续查询最终结果并自动重试临时网络错误；遇到限流延迟 60 秒，过期提示重新生成。短信验证完成后继续查询，支持手动检查状态。

“手机已确认”不等于平台已签发登录 Cookie；上游 confirmed 分支仍返回 scanned，只有拿到真实会话才返回 success 并保存。轮询与 UI 修复已有测试，用户账号是否最终授权仍需真实扫码复测。
